CHANGES - Vulkan sphere renderer
================================

Build & run:
  cmake -S . -B build && cmake --build build && ./build/my_engine


PART 1 - BUILD FIXES
--------------------

PART 4 - NEW FUNCTIONALITY (drawing the sphere)
-----------------------------------------------

Device (src/device.cpp)
  - Creates one queue per distinct queue family.
  - Enables the VK_KHR_swapchain device extension.
  - destroy() waits for the device to be idle before destroying it.

Swapchain (src/swapchain.cpp)
  - Finished Swapchain::create: picks image count (min + 1), format, present
    mode, extent and composite alpha, and sets the queue sharing mode
    (concurrent if graphics and present families differ).
  - Added chooseCompositeAlpha() helper.
  - Implemented createImageViews().
  - create() destroys the old swapchain first, so it can be called on resize.

Shaders (new folder content)
  - shaders/sphere.vert: transforms vertices with an MVP matrix (push
    constant) and passes the normal to the fragment shader.
  - shaders/sphere.frag: simple diffuse lighting from one direction plus a
    small ambient term.
  - CMakeLists.txt compiles them with glslc into build/shaders/*.spv and
    passes that folder to the code as SHADER_DIR.

Renderer (src/renderer.cpp, headers/renderer.hpp)
  - Validation layer (VK_LAYER_KHRONOS_validation) enabled automatically in
    non-release builds when it is installed.
  - createDepthResources: depth image, memory and view (picks a supported
    depth format).
  - createRenderPass: color + depth attachments, cleared every frame.
  - createPipeline: loads SPIR-V shaders, vertex layout matching Vertex
    {position, normal}, depth test on, back-face culling (counter-clockwise
    front faces), dynamic viewport/scissor, push constant range.
  - createFramebuffers: one per swapchain image.
  - createCommandObjects: command pool + one command buffer per frame in flight.
  - createSyncObjects: per-frame semaphore and fence, plus one
    "render finished" semaphore per swapchain image.
  - uploadMesh: creates vertex and index buffers (CPU-writable memory) and
    copies the mesh into them. Can be called again to replace the mesh.
  - findMemoryType / createBuffer helpers.
  - recordCommandBuffer: clears the screen, binds pipeline and buffers, sets
    camera (perspective, camera at z = 6, Vulkan Y-flip) and model rotation
    around Y, then draws the sphere.
  - drawFrame: 2 frames in flight; wait fence -> acquire image -> record ->
    submit -> present.
  - Window resize: swapchain, depth buffer and framebuffers are rebuilt when
    Vulkan reports OUT_OF_DATE/SUBOPTIMAL or when the window size changes
    (needed on Wayland, which doesn't report OUT_OF_DATE).
  - Minimized window: no drawing while the framebuffer is 0x0.
  - shutdown: frees mesh buffers, sync objects, command pool, pipeline,
    swapchain resources, render pass, device, surface and instance.


PART 5 - SCENE: BALL ON A PILLAR + TWO PILLARS
----------------------------------------------

New files headers/box.hpp, src/box.cpp
  - createBox(width, height, depth): box mesh standing on y = 0 (origin at the
    center of its bottom face), flat normals per face, counter-clockwise
    triangles seen from outside. Used for the pillars.
  - src/box.cpp added to CMakeLists.txt.

Renderer - several objects instead of one mesh
  - uploadMesh() now returns a mesh id and can be called many times.
  - New addObject(meshId, model matrix, color): one thing to draw. Several
    objects can share one mesh (both pillars use the same box).
  - recordCommandBuffer draws every object with its own matrix and color.
  - Camera: at (0, 4, 10), looking at (0, 2, 0), so both pillars are visible.
  - The sphere no longer spins.
  - destroyMeshBuffers() replaced by destroyMeshes() (frees all meshes).

Shaders
  - Push constants are now { mat4 mvp; vec4 color; mat3 normalMatrix }
    = 128 bytes (the size every GPU supports).
  - Color comes from the object instead of being hard-coded in the shader.
  - Normal matrix = inverse-transpose of the model matrix, so lighting stays
    correct for scaled objects.

src/main.cpp - the scene
  - Two grey pillars (0.6 x 3.0 x 0.6) at x = -3 and x = +3.
  - White ball (radius 0.5) lying on top of the first pillar.
  - Sizes are named constants at the top of the scene setup
    (pillarWidth, pillarHeight, pillarDistance, ballRadius), so the bridge
    can later be placed between the pillar tops at y = pillarHeight.


PART 6 - WIDER PILLARS, SMALLER CHECKERED BALL
----------------------------------------------

src/main.cpp
  - pillarWidth 0.6 -> 1.2, ballRadius 0.5 -> 0.3.
  - Ball is green/white checkered: ballGreen, ballWhite, ballSquares = 4
    (4 rows of squares, 8 around).

Vertex (headers/sphere.hpp)
  - New field glm::vec2 uv (texture coordinates 0..1). Also needed later for
    textures.
  - createSphere: u goes around the sphere, v from top to bottom.
  - createBox: each face gets UVs 0..1.

Renderer
  - addObject(meshId, model, color, checkerColor = 0, checkerSquares = 0):
    checkerSquares > 0 paints a checker pattern of color and checkerColor.
    Old calls with 3 arguments still work (solid color).
  - Pipeline has a 3rd vertex attribute (uv, location 2).
  - Push constants are still 128 bytes: the checker data uses spare parts
    (color.a = number of squares, normal matrix .w = checker color).

Shaders
  - sphere.vert passes UV and checker data to the fragment shader.
  - sphere.frag picks color or checkerColor per square:
    floor(u * squares * 2) + floor(v * squares), even/odd.


TESTED
------
  - Builds with -Wall -Wextra and no warnings.
  - Runs with the validation layer active and no validation errors.
  - Captured frame shows two wide grey pillars on a black background with a
    small green/white checkered ball lying on top of the left pillar.
  - Not tested by hand: resizing and minimizing the window.


NOTES
-----
  - Mesh buffers use CPU-writable memory. Fine for a small mesh; a bigger
    scene would use a staging buffer and GPU-only memory.
  - The pillars lean slightly in the picture: that is normal perspective,
    because the camera looks down at them a little.
